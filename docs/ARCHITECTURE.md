# Архитектура MLFuzzZ3

Проект исследует сочетание мутации входов и I2S+SMT. Схема действующего
пути приведена в [README](../README.md), роли компонентов —
в [описании задумки](../PROJECT_VISION.md).

## Реализованные компоненты

| Компонент | Код | Назначение |
| --- | --- | --- |
| Оркестратор кампании | `src/core/` | Выбор входа, мутации, учёт покрытия, сохранение корпуса и обработка сбоев |
| Мутатор | `src/mutation/` | Детерминированные стадии и случайные изменения входов |
| Инструментация | `src/instrumentation/` | LLVM-проходы покрытия и конкретных операндов сравнений |
| Рантайм цели | `src/runtime/coverage/` | Запись покрытия и сравнений в разделяемую память |
| Чтение обратной связи | `src/coverage/` | Декодирование карты и журнала сравнений |
| I2S-фронтенд | `src/concolic/` | Поиск значений сравнений в байтах входа и построение битовых ограничений |
| Решатель | `src/solver/` | Решение построенной системы через Z3 |
| Исполнение | `exec-server/` | Запуск отдельного процесса цели на вход, таймауты и результаты исполнения |
| Транспорт | `src/ipc/`, `exec-server/internal/ipc/`, `proto/` | Обмен protobuf-сообщениями и передача дескрипторов памяти |

Ядро C++ и сервер Go работают в разных процессах. Ядро запускает сервер
как внутренний подпроцесс; канал управления — Unix socketpair с наследуемым
дескриптором. Дескрипторы memfd передаются через SCM_RIGHTS.

При стагнации покрытия оркестратор может попытаться построить кандидат
через I2S+SMT. Бюджет ограничивает стоимость этого пути. Кандидат исполняется
обычным сервером и проходит общую обработку результата.

## Границы метода

Журнал сравнений содержит конкретные значения, а не символьный путь.
Привязка по совпадению значений эвристическая. SAT/UNSAT относится к
построенной системе; корректность её связи с программой не доказана.
Новое покрытие не доказывает инверсию выбранного сравнения. Коллизии ключей
сайтов и переполнение журнала ограничивают интерпретацию наблюдений.

Полного символьного исполнения, taint-анализа и символьной памяти нет.
Историческое имя `concolic` обозначает нынешний I2S+SMT-путь.

## Планируемые компоненты

Продуктовый LLM-бэкенд, детерминированный планировщик потоков, собственный
sanitizer и воспроизведение расписаний пока не реализованы. Требование к
будущему LLM-пути: предложения проверяет Z3, окончательный вердикт не
выдаётся языковой моделью, компонент полностью отключаем.
Persistent mode также остаётся будущей работой.

Контракты: [IPC](IPC.md), [инструментация](INSTRUMENTATION.md).
Состояние исследования: [текущая карта](CURRENT_STATE.md).

## Композиция кампании (ADR-0056)

`src/core` содержит доменные ExecutionResult, ExecutionService, Stage,
CorpusView, StrategyPolicy, AdmissionPolicy, Objective и EventSink.
CampaignLoop исполняет решение политики, проверяет лимиты и обрабатывает
результат; он не включает IPC/protobuf или concolic и не меняет layout
через макрос сборки. Отдельный тест domain campaign линкуется только с core.

`src/composition` собирает встроенные компоненты и транспортный адаптер.
Исторический Runner/SessionRunner сохранён для исследовательских утилит и
совместимого конструктора, реализация которого находится в composition.
RunnerBackend копирует сравнения только для запрошенного сбора (RunPurpose
comparisons), непосредственно после своего Run. Мутационные исполнения не
материализуют ненужный журнал; comparisons_available отличает отсутствие
снимка от пустой полной или неполной трассы. ExecutionService присваивает локальный номер попытки; серверный run_id
сохраняется отдельно. Переполнение SHM обозначается флагом неполных наблюдений.

Стадии deterministic, mutation, I2S и I2S+SMT возвращают один кандидат или
типизированный исход. Им не передаются корпус, IPC или хранилище findings.
Детерминированная стадия рассчитывает следующий курсор; для первого переноса
его запись остаётся в Corpus, как требует [план миграции](MODULARITY.md).
Политики и планировщики получают только CorpusView с метаданными; результат
уведомляет SeedScheduler отдельно от выбора стадии. Havoc собирает меню
операторов, OperatorSelector и StackingPolicy. Default сохраняет порядок
меню и потребления RNG; YAML может выбрать подмножество операторов.

ExecutionService централизованно проверяет глобальный и локальный лимит перед
каждым запросом исполнения, включая подготовку сравнений. Копирование сервиса
запрещено, чтобы не дублировать счётчики. Таймаут решения пересчитывается после
построения системы и AST. Кооперативная отмена проверяется между подэтапами
реконструкции, поиска привязки и построения AST; активный вызов Z3 ограничен
таймаутом. Уже начатое исполнение цели завершается в рамках существующего
таймаута Go-сервера; max_seconds не означает немедленное прерывание этого Run.
CPU процесса контроллера и wall-time записываются раздельно. CPU дочерней цели
и сервера не измеряется этим счётчиком; CPU-бюджет не объявляется реализованным.

Профили: legacy, mutation-only, hybrid-heuristic, hybrid-ml. Legacy сохраняет
det-first, прежний RNG, стагнацию и адаптивный throttle. Исправлено превышение
max_iterations между подготовкой и проверкой кандидата. Его прежняя обработка
подготовки сохраняется: запрос виден в счётчиках/журнале, но не добавляет edges
или findings. Новые гибридные профили явно учитывают результаты подготовки;
сам уже имеющийся сид повторно не добавляется в corpus. Историческая
классификация width-overflow в legacy-счётчике no_binding сохранена, а новый
типизированный журнал обозначает этот исход как solver_error.

Дешёвая I2S использует существующий ValueMatchBinding, вынесенный в отдельную
библиотеку без Z3. Это конкретные предложения замены поля; исполнение кандидата
обязательно. Полноценного taint/shadow или доказательства инверсии сайта нет.
Hybrid-heuristic пробует I2S и затем SMT по стагнации. Экспериментальный
hybrid-ml использует контекстный epsilon-greedy: признаки — размер входа и
стагнация; действия — mutation, I2S и SMT с бюджетами 1/10/100/1000 мс в
пределах конфига. Награда `(наблюдаемые новые edges + 4 * findings) / execs`
получается только из исполнений, включая стоимость подготовки. SAT/UNSAT сами
по себе награды не дают. Недоступные действия маскируются; отсутствие привязки
откладывает соответствующую руку на 64 решения. Обучение начинается заново
для каждой кампании; внешняя модель и её checkpoint не заявляются.

Версионированный YAML описан в CONFIG.md; profile defaults < явный YAML <
явный CLI. Имена и параметры проверяются до запуска сервера, capabilities
каналов — после handshake до первого исполнения. Проверка каналов не является
доказательством инструментированности произвольного бинарного файла цели.
Сохраняются resolved.yaml, run-manifest.yaml и events.jsonl с параметрами,
ревизией, seed, версиями модулей, ресурсами решений и результатами исполнений.

`FUZZER_ENABLE_I2S` управляет дешёвой стадией независимо от Z3;
`FUZZER_ENABLE_SMT` — регистрацией солверной стадии;
`FUZZER_BUILD_Z3` — сборкой солверной библиотеки и исследовательских API.
Mutation-only работает без Z3. Это не coverage-only инструментация: прежний
CLI по-прежнему согласует два канала с Go. Wire-протокол и серверный frontier
не меняются. Полная реализация и границы — MODULARITY.md и ADR-0056.
