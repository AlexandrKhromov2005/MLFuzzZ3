# Участие в проекте

Предложение изменения должно описывать проблему, ожидаемый результат и
способ проверки. Изменения публичного API и схем IPC обсуждаются заранее.
Нетривиальные архитектурные решения фиксируются отдельным документом.

Код C++ использует C++20; Go — версии из `exec-server/go.mod`.
Новый модуль сопровождается тестами, исправление ошибки — проверкой,
воспроизводящей исходную проблему. Перед отправкой изменения выполняются
сборка, тесты, форматирование и статический анализ; команды находятся
в [инструкции](docs/DEVELOPMENT.md).

Сообщения коммитов пишутся на английском в формате Conventional Commits:
`fix:`, `feat:`, `docs:`, `test:`, `build:` и другие стандартные типы.
Один коммит описывает одно логическое изменение. Документация и объяснение
исследовательских результатов пишутся на русском.

Выводы должны опираться на данные. Отрицательные результаты сохраняются;
завершённое измерение явно отделяется от сценария и будущей работы.
