# Задумка проекта

MLFuzzZ3 исследует сочетание быстрого мутационного поиска с более дорогими
методами направленного получения входов. Цель — измерить, где дополнительная
информация о программе помогает покрывать сложные ветви, а где стоимость
анализа превышает пользу.

## Действующие компоненты

| Компонент | Назначение | Граница текущей реализации |
| --- | --- | --- |
| Оркестратор кампании на C++ | Выбирает входы, запускает мутации, учитывает покрытие и включает SMT-путь | Гибридный цикл mutation + I2S+SMT |
| Корпус и планировщик входов | Хранят полезные входы и распределяют попытки | Выбор входов, без поиска расписаний потоков |
| LLVM-инструментация и рантайм | Собирают покрытие и конкретные значения сравнений | Значения операндов, без символьной интерпретации программы |
| Сервер исполнения на Go | Запускает цель, контролирует выполнение и возвращает результаты | Отдельный процесс для каждого входа |
| I2S-привязка | Сопоставляет значения сравнений с байтами входа | Эвристика, а не доказанный поток данных |
| SMT-подсистема и Z3 | Строят и решают битовые ограничения для кандидата входа | Вердикт о построенной системе, не о достижимости произвольной ветви программы |
| Проверка кандидатов | Исполняет вход и измеряет наблюдаемый результат | Проверка исполнением и покрытием, без автоматического доказательства инверсии сайта |

Схема действующего пути приведена в [README](README.md).
Подробная карта реализации — [CURRENT_STATE.md](docs/CURRENT_STATE.md).

## Будущая архитектура

Исходная задумка шире действующего прототипа. Перечисленные ниже компоненты
пока не реализованы и не входят в заявления о текущих возможностях.

- **LLM-помощник решателя:** предлагает преобразования формул и подсказки.
  Предложения проверяются через Z3; LLM не выносит финальный SAT/UNSAT.
  Компонент должен полностью отключаться.
- **Детерминированный планировщик потоков:** управляет расписаниями для
  воспроизводимого исследования многопоточных ошибок.
- **Собственный sanitizer:** собирает сигналы ошибок памяти и гонок.
- **Persistent mode:** повторное исполнение входов с корректным сбросом
  состояния цели, вместо запуска нового процесса на каждый вход.

Полное символьное исполнение с taint/shadow и символьной памятью исключено
из текущего охвата. Будущие компоненты требуют отдельного проектирования,
реализации и экспериментальной проверки.

## Принципы исследования

1. Утверждение сопровождается измерением и описанием условий.
2. Эвристическая модель отделяется от поведения реальной программы.
3. Ускорение оценивается вместе со стоимостью исполнения и анализа.
4. Отрицательные результаты и ограничения сохраняются.
5. Эксперимент воспроизводится по версии кода, конфигурации, входам и сырью.

Текущее состояние не объявляет исходную задумку полностью выполненной.
